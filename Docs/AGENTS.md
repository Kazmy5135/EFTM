# AGENTS.md - EFTM 策划设计与项目文档

## 定位

`Docs/` 是 EFTM 的策划、技术、迭代、研究和追踪知识库。策划设计任务默认以本目录为工作根目录，不使用 H5 或 Unity 当前实现反推玩家规则。

## 项目入口

开始任务前按需要读取：

1. `README.md`
2. `00_Project/ProjectStatus.md`
3. `00_Project/DocumentationRules.md`
4. `00_Project/ProjectWorkflow.md`
5. 相关 `10_Design` 当前设计
6. 相关 `20_Technical` 当前技术契约
7. 当前 `30_Iterations` 工作项

Agent 职责与交接入口为 `00_Project/Agents/README.md`。

## 策划设计职责

- 维护产品范围、玩家体验、玩法规则、边界、验收标准和设计取舍。
- 区分正式设计、技术契约、实现事实、研究推论和实验结果。
- 判断某项设计是否需要 H5 体感验证。
- 评审 H5 证据并决定确认、修订或继续验证，不把实验结果自动写成正式结论。

## H5 可选验证规则

- H5 不属于每个设计工作项的固定步骤。
- 只有设计者明确提出需要原型验证时，策划设计 agent 才建立或更新相应工作项，并向 H5 agent 发出明确交接。
- 交接至少说明验证假设、目标体验、原型范围、非目标、目标设备和成功/失败判据。
- 如果没有明确触发，不得把“先做 H5”添加为设计评审或 Unity 开发门禁。

## 权威与状态

- 当前阶段与下一门禁：`00_Project/ProjectStatus.md`。
- 当前设计规则：`10_Design/`；只有 `accepted` 可作为正式实现依据。
- 当前技术契约：`20_Technical/`；只有 `accepted` 可作为正式技术基线。
- 工作过程和验证证据：`30_Iterations/`，不自动成为当前规则。
- 外部来源与实验推论：`40_Research/`。
- 实现状态对应关系：`00_Project/TraceabilityRegister.md`。

聊天、研究、H5 原型和 Unity 实现都不能静默覆盖正式设计。冲突必须分类为设计变更、技术修订、实验限制或实现偏差。

## 工作规则

- 新设计或语义变更先进入工作项，再形成或修改正式基线。
- accepted 设计在变更讨论期间保持有效；获批后原子同步受影响的权威文档。
- 正式设计描述可观察行为与验收，不绑定 H5 或 Unity 的具体代码结构。
- 纯策划任务默认不读取 `H5Prototype/` 或 `UnityProject/`；只有原型评审、技术接入或一致性校验时才跨目录。
- 不把“已经实现”当作“设计正确”，也不为迁就实现静默改变规则。
- 除非用户明确要求，不编写 H5 或 Unity 实现。
