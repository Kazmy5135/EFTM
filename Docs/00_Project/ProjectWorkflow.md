# 项目文档与交付工作流

## 三层权威

| 层级 | 回答的问题 | 主要产出 |
|---|---|---|
| 设计 | 做什么、为什么、用户看到什么、怎样算正确 | 设计规格、DDR |
| 技术 | 如何实现、职责在哪里、如何迁移和验证 | 技术规格、ADR |
| 实现 | 当前代码、配置、资产和测试实际是什么 | 代码、资产、测试证据 |

## 标准链路

1. 明确工作类型、目标、范围、非目标、负责人和验收方式。
2. 在 `30_Iterations` 创建工作记录。
3. 新主题建立 draft；修改 accepted 主题时先在工作记录中讨论差异。
4. 设计完成评审并批准为 accepted，或将设计变更应用到当前基线。
5. 技术规格绑定准确的设计基线，完成评审并批准。
6. 实现任务绑定设计和技术基线，拆成可独立验证的切片。
7. 执行测试、系统验证和可观察行为验收。
8. 更新 `TraceabilityRegister.md`、工作记录和项目状态。

## 门禁

- 设计门禁：目标、规则、边界和验收没有阻断性待决策项。
- 技术门禁：职责、依赖、数据、接口、失败路径、迁移和验证明确。
- 开发门禁：任务绑定当前 accepted 设计与技术基线，并有回退方式。
- 收口门禁：证据可定位，冲突有归属，追踪登记已同步。

实现与基线不一致时标记 `diverged`，不得通过改写文档掩盖失败。
