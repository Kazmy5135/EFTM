# U5 设备验收交接

本记录只定义已批准 V1 的验证步骤，不增加玩法。工作项 006 保持 verifying，需设计者体验确认后关闭。

## 当前交付入口

- Unity `2022.3.62f2`，打开 `Assets/_Project/Scenes/CombatFoundationV1.unity` 后 Play。
- 正常应用入口仍为 `Bootstrap` → `CombatFoundationV1`。
- 桌面开发包：`UnityProject/Builds/CombatFoundationV1-Windows/EFTM-V1.exe`；整个同名目录须一起保留，含字体许可证。Builds 是本地忽略目录，不提交。
- Windows 参考窗口 540×1080；UI 设计坐标仍为 1080×2160。不能把桌面窗口结果当作手机验收。
- 测试种子 `20260904`；敌人换位和水平后坐力共用确定性随机源。射击次数不同会影响后续随机序列，这是当前模型契约。

## 真机前置条件

1. 为现有 Unity **2022.3.62f2** 安装 Android Build Support，包含 SDK、NDK 和 OpenJDK；不能换用另一 Unity 版本构建来代替。
2. 指定并接入一台 Android 手机，在设备上由用户授权 USB 调试。记录型号、系统版本、分辨率、安全区和刷新率。
3. Development Build，Portrait，场景顺序 Bootstrap / CombatFoundationV1；输入后端保持 Input Manager (Old)。当前未引入新 Input System。
4. iOS 仍需要 macOS/Xcode 和对应设备环境，不在 Windows 上伪造已验证结果。

## 同脚本对照 H5 V1 与 Unity

| 操作 | 通过条件 | 真机结果 |
|---|---|---|
| 初始停留 | 近墙遮挡真实敌人，边缘仍有通道；无实时透视 | 待确认 |
| 按住假动作约 0.4 秒，再松开 | 300ms 探出、240ms 返回；不能射击；达到 10% 时“已预瞄” | 待确认 |
| 返回后停留 | 黄色人形在最后观察位置；提示这可能是过期情报 | 待确认 |
| 点击真架枪后立即按住开火 | 按键立即可用，探出中只预备，完全暴露后才射击 | 待确认 |
| 松开开火，再按住连续射击 | 松手停火但保持架枪；下一轮从首发后坐力开始 | 待确认 |
| 持续开火并下拖手指 | 前 4 发上跳/爬升，第 5 发后稳定；下拖能压枪，左右拖动方向自然 | 待确认 |
| 中央非按钮区域拖动 | 可以调瞄；控件不会被中央输入面抢走；真架枪再次返回 | 待确认 |
| 无新假情报直接再次真架枪 | 保留手动准星，不反复吸附 | 待确认 |
| 重复假动作/返回/架枪 | 敌人可能换位；旧情报不跟踪新位置；重新观察可更新预瞄 | 待确认 |
| 长按时切后台、系统手势中断后恢复 | 停火并安全回撤，不留卡住的指针 | 待确认 |
| 连射 60 秒、反复真假动作 | 无明显首次射击卡顿、无持续 GC 峰值，帧时可接受 | 待确认 |

## 必须记录

- 分别记录 60Hz / 30Hz 设备帧时、GC、第一次射击与稳定连射的最大帧耗时。
- 记录 1080×2160 与另一长宽比/安全区下的触达、中文显示和按钮尺寸。
- 记录 H5/Unity 的可接受差异、失败差异和设计者结论；桌面自动化不是手感结论。
- 五点位当前采样档位是 20/50/70/65/100%，并非 H5 的 15/35/65/65/100%。设计只要求不同露出位置与 10% 情报阈值；该空间差异需人工对照，不静默改设计。
- 若要追加弹匣、伤害、换弹、AI 或背包接入，先建立新的 accepted 设计/技术工作项，不能以“继续开发”为由跨过当前边界。
