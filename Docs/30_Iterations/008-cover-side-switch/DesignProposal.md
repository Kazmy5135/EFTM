# 双侧掩体换边与移动观察

## 1. 阅读说明与定位

> 本文保留初版审批历史。2026-09-08 体验后的[直视通道换边修订](DirectSwitchRevision.md)已获确认，替代本文预转头/回看流程；现行规则为立即横移 0.80s、全程面朝通道、不自动跟踪敌人。以正式设计正文和该修订为准。

设计者于 2026-09-08 明确“设计通过”，本稿作为批准的变更记录保留，规则已同步至 `../../10_Design/CoreCombatDesign.md` 与 `DDR-001`。下文“建议/待整体审批”等措辞保留评审时原文，不再表示审批悬而未决；整体推荐规则已获批准，未指定的时长仍由技术稿提出可调初值。本记录不是第二份长期权威规则，也不是技术开发授权。

设计路线：**固定双掩体点位之间的承诺式换边，利用移动视野获取情报**。不引入自由行走、摇杆或多条独立战线，不在抵达后追加自动假 Peek。保持手机 `1080 × 2160` 竖屏、单手可完成和现有真假 Peek/开火基本分工。

本次已批准改变“只有一处玩家掩体”和“只有手动假动作才能建立情报”两条约束；旧 H5 与 Unity 单侧实现不因此自动满足新设计。

## 2. 用户已明确的需求

- 玩家近端由一个石板调整为左右各一个石板。
- 玩家利用两个石板之间的中央开口观察、架枪：在右侧点位向左 Peek，在左侧点位向右 Peek。
- “假动作”按钮上方新增换边按钮，切换玩家所在点位。
- 换边需要连续地跑到另一个石板后面，不是镜头瞬移或场景翻转。
- 开跑前先朝目的点转头；开跑后视线向通道方向转回。
- 跑动回看和抵达过程中的实际视野使用假动作的识别逻辑，敌人可见轮廓达到 `10%` 时获取情报；设计者已确认这一阈值与获取窗口。
- 设计者明确否决抵达后的自动观察动作，不追加自动探头、观察停留或探出再缩回的循环；后续主动观察仍由玩家按住假动作触发。
- 只有完全回到掩体后才允许换边，此发起条件已由设计者确认。
- 模型修改必须走 Blender 流程：修改 Blender 源模型，再导出并接入 Unity，不直接在 Unity 中改造模型。
- 先审批设计，再做技术文档，技术审批后再实施。

“站在两个石板中间”在本稿中解释为使用两块石板的内侧边缘和中央通路，不是固定站在通道正中心、只切换镜头。该空间解释随本稿一并确认。

## 3. 空间与操作

左右始终以玩家面向通道尽头时为准，不随临时转头改变命名。

| 玩家点位 | 隐藏位置 | Peek 方向 | 换边目的地 |
|---|---|---|---|
| 右侧 | 右石板近端的内侧边缘后 | 向左探出，侧倾方向匹配 | 左侧石板后 |
| 左侧 | 左石板近端的内侧边缘后 | 向右探出，侧倾方向匹配 | 右侧石板后 |

- 两块石板之间保留可连续穿行的通路；不能只复制模型而把路线堵住。
- 两侧隐藏位均应挡住真实敌人，同时画面边缘保留有限通道；完全 Peek 后应打开朝通道尽头的视野。
- 初始点位建议继续为右侧，保持原有向左 Peek 的入场认知。
- 保留左下真架枪、右下假动作、中央按住开火；换边键放在假动作键正上方，并排除在中央拖动调瞄区域之外。
- 换边键建议显示目的地：“换到左侧”或“换到右侧”；信息栏显示“左侧掩体 / 右侧掩体 / 换边中”。
- 单次点击触发，无需长按；一次只执行一个换边动作，不缓存连续点击。

## 4. 换边过程与镜头

| 阶段 | 从右到左 | 从左到右 | 体验约束 |
|---|---|---|---|
| 起步前 | 先向左转头，看左侧目的点 | 先向右转头，看右侧目的点 | 玩家位置暂不改变；先看清要去哪 |
| 跑动 | 身体持续向左移动，镜头开始向右转回通道 | 身体持续向右移动，镜头开始向左转回通道 | 平移和回看重叠发生，不等跑完才回头 |
| 抵达过程 | 向左侧隐藏落点减速，视线已转回通道 | 向右侧隐藏落点减速，视线已转回通道 | 利用尚未被石板挡住的实际视野获取情报，不额外探身 |
| 完成落位 | 停在左石板后，下一次手动 Peek 向右 | 停在右石板后，下一次手动 Peek 向左 | 不追加自动观察，恢复玩家对真假 Peek 的选择 |

- 镜头必须有真实平移造成的视差；禁止黑屏切换、瞬移、镜像画面或转头掩盖瞬移。
- 跑动时视线转回通道，但不自动追踪敌人；这是预设方向的回看，不是换边时自动瞄准。
- 轻微跑动起伏可以作为后续表现调优，不是本轮必须新增的强晃动效果。
- 保持 horizon 可读，避免横移、快速转头和剧烈倾斜叠加导致眩晕；两方向都需单独体验验收。
- 换边总时长、预转头时长和抵达减速时长尚未由用户指定。本稿不把任何时长标为已批准；建议先用短促但能读清各阶段的表现，由技术稿提出可调参数，再经体验确认。不设置额外的自动观察停留时长。
- 原地普通 Peek 的 `300ms` 探出、`240ms` 返回与约 `7°` 侧倾保持原基线；不把整段跑动压缩成 300ms Peek。

### 到达后的处理：按设计者反馈修订

删除原提案的“抵达后自动假 Peek → 短暂观察 → 自动缩回”。换边不替玩家按下假动作；玩家想再次探头，需要手动操作。

本稿据此将动作落点整理为目标石板后的隐藏位置：看到敌人的机会来自跑动回看和抵达路径本身，而非落位后额外探出。抵达过程按 `10%` 阈值记录真实所见，不能为获取情报强行穿透石板或凭空显示敌人。

完成落位时，如本次换边取得有效情报，建议显示其最后观察位置的黄色剪影；没有有效情报则不生成。此高亮衔接随修订稿整体审批，不将“取消自动观察”误解为取消已同意的移动情报识别。

## 5. 操作互斥与中断（推荐补全）

- 已确认仅在完全回到掩体后允许换边；真架枪、射击、手动假 Peek 和返回过程中不可点击。提示文案建议为“先回到掩体”。
- 换边为承诺动作：开始后不能通过第二次点击取消或反向，不需要持续按住，也不支持拖动控制跑动方向。
- 换边及抵达落位过程中暂停真架枪、手动假动作、开火及手动调瞄，不接受预备开火；完成落位后恢复。
- “真架枪开始即可预备开火”仍适用于普通真架枪，不扩展到换边。
- 系统暂停/失焦不能导致残留按住开火或卡死在不可操作状态。建议暂停当前移动，恢复后继续完成到安全落点的动作；不因系统打断瞬移穿墙。技术稿需明确各平台暂停时序。
- 本轮不引入受击、无敌帧或换边命中概率；早期草案的“20% 被命中”不自动生效。移动暴露只通过真实空间与遮挡表达。

## 6. 观察、黄色剪影与跨点位预瞄（推荐补全）

### 观察阈值

- 复用假动作的真实可见轮廓阈值：达到或超过 `10%` 才获得有效情报，不降为“出现一个像素即可标记”。
- 已确认跑动回看和抵达过程中均可按 `10%` 阈值获取或更新情报；起步前看目的地不额外扫描敌人。
- 只记录实际看到的最后位置，未达阈值不产生新信息；每次有效观察允许更新，直到敌人被挡住或观察结束。
- 到达后不延长情报采样窗口、不自动探头。完成落位后的新观察由手动假动作触发。

### 高亮时机

- 本稿建议保留原 V1 的黄色历史剪影语义：换边开始隐藏旧剪影；获得情报时信息栏更新“已预瞄”；完成换边并落入目标石板后的隐藏位置时，在最后观察位置显示黄色发光人形。这里没有额外的 Peek 或缩回动作。
- 如果这次换边没有达到阈值，不生成新剪影，也不自动重显已隐藏的旧剪影；原历史情报是否仍有效按 V1 保留，不把“旧信息”写成“这次看到了敌人”。
- 黄色剪影不得跟踪已经移动的敌人，不能通过转头或换边把未见位置高亮出来。
- 下一次真架枪、假动作或换边开始时隐藏剪影。

### 自动预瞄

- 新的换边观察情报与手动假 Peek 情报一样，为下一次真架枪提供一次旧位置预瞄，不在跑动过程中自动吸附。
- 玩家换边后，预瞄仍应指向被观察到的同一个世界位置，不能沿用旧站位的屏幕坐标或角度造成错位，也不能改成敌人最新位置。
- 无新情报时不重复吸附；建议保留已有手动瞄准方向，不因为换边自动锁敌。其在不同站位下的屏幕变化属于视差，不保证准星仍落在同一个物体上。

### 敌人 25% 换位的衔接

- 保留五个敌人点位与 `25%` 概率，不新增 AI。
- 建议把整段换边至抵达落位视为一次完整的移动情报获取过程；完成落位并完全隐藏后结算一次敌人换位，不依赖自动假 Peek 动作。
- 起步转头、跑动途中暂时看不到敌人、经过某个遮挡边缘，都不各自触发随机换位。
- 敌人不能在可见时因这条规则瞬移；先恢复隐藏，再进行换位判定。已记录剪影保持旧位置，因此依然可能过期。
- 换边出发前不额外结算一轮；此前普通 Peek 已完成的换位不重复结算。

## 7. 建模与场景修改范围

本节是美术与空间的设计交付要求，不指定程序组件、数据结构或导出实现方式。

### 可编辑模型

- Blender 是本次模型几何与环境布局修改的权威入口；先修改原有 Blender 源文件及相应生成脚本（如有），保存可编辑结果，再重新导出模型。
- 将近端单侧石板布局改为左右两块具有真实厚度的石板，保留仓库风格和通道纵深。
- 配套调整近端地面、墙体连接和会挡住换边路线的道具，避免悬空、夹缝、穿模和路线突然变窄。
- 不在 Unity 中通过复制/拼接石板、创建替代几何体、修改网格或仅改变环境构件摆放来实现双侧布局；需要修改形状、尺寸和环境相对位置时返回 Blender，再导出接入。
- 可以复用原石板材质与构件，不要求为换边整体重做仓库或引入全新角色美术。

### Unity 场景

- Unity 只负责导入 Blender 导出的环境、更新资产引用和场景接入、材质/碰撞及玩法配置与验证，不承担模型改造。可见石板与实际阻挡范围必须一致；旧石板不得在新模型背后残留为不可见障碍。
- 配置左右隐藏位置、对应反向 Peek 的观察空间，以及两点之间连续可走的路径和完整镜头活动空间。
- 玩家空间位置和镜头一起完成换边；不能只移动观察镜头、仍让玩家位置停留在出发点。
- 现有五个敌人点位需要从左右两侧重新检查遮挡；不假设一侧可见性测试能覆盖另一侧。
- 允许左右侧暴露比例不同，但两侧分别都要能形成有效观察/攻击机会。若某敌人点位两侧都无法观察，应调整挡物或提出设计问题，不能偷偷降阈值。
- 保留既有射击/预瞄目标和黄色剪影的空间一致性，不能用高亮掩盖场景视野错误。

后续技术稿必须覆盖“Blender 源模型修改与检查 → 导出 → Unity 导入/场景接入 → 双侧遮挡与镜头路径验收”的完整链路，沿用 007 的美术流程；具体资产清单在技术阶段核实。发现空间问题时返回 Blender 修正，不以 Unity 临时几何补丁作为最终交付。

## 8. 验收案例

- [ ] 右侧向左 Peek，左侧向右 Peek，位移与侧倾都正确。
- [ ] 两侧隐藏位均有真实遮挡，画面边缘可见部分通道；探出后能获得有效视野。
- [ ] 单手点击假动作上方的换边按钮可执行，且不会误触调瞄；按钮目的地和实际落点一致。
- [ ] 右到左、左到右均是“先看目的地 → 连续跑动并回看通道 → 抵达另一侧石板后”，无瞬移、穿模或方向突变。
- [ ] 抵达后不自动探头、不增加观察停留，不执行额外探出/缩回循环；再次观察需要玩家按假动作。
- [ ] 低于 10% 不更新情报，达到 10% 更新；起止阶段、无敌人和中途遮挡分别可验证。
- [ ] 有效观察后的黄色剪影位于最后所见位置；敌人换位后不跟踪，下一动作开始时消失。
- [ ] 跨侧真架枪预瞄旧世界位置，而不是旧屏幕位置；没有新情报不重复吸附。
- [ ] 一次换边只在最终隐藏时结算一次 25% 换位，转头和中途遮挡不重复触发。
- [ ] 连点、按住其他按钮、系统失焦/暂停均不产生移动中开火、动作叠加或输入卡死。
- [ ] 双石板与关联环境修改可追溯至 Blender 源文件；源模型、导出资产和 Unity 场景一致，无 Unity 独有的模型/布局补丁；两侧各自检查全部五个敌人点位与镜头路径。
- [ ] 手机竖屏下可读、可单手触达；转头跑动不产生不可接受的眩晕。原 V1 普通 Peek、开火和压枪无回归。

3. 同意跑动回看和抵达过程按现有 `10%` 阈值获取情报；复用识别规则不等于自动触发假动作。
