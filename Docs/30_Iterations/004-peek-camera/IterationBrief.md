# 004 - 3D 摄像机 Peek 视角验证

## 问题与背景

上一版 H5 同时实现战斗、弹匣、换弹、切换掩体与反馈，已经不适合作为摄像机 Peek 体感的单变量实验。设计者要求废弃该当前实现，在 Git 保留历史，并用同一手机 H5 运行架构重做只验证视角的真 3D 原型。

## 验证假设

玩家默认位于通道入口右侧的近墙后，真实几何遮挡使其完全看不到通道内部；按住 `PEEK` 时，摄像机横向移动并侧倾，逐渐露出通道纵深；松开后立即缩回墙后。该变化应让玩家不依赖说明文字也能感到“身体正在离开掩体观察”。

## 范围

- 1080×2160 手机竖屏与单指输入。
- 一处固定右侧近墙掩体。
- 一个具有明显纵深、灯光、结构重复和近远参照物的真 3D 工业通道。
- 按住探头、保持观察、松开缩回的摄像机状态与表现。
- 同局域网手机访问。

## 非目标

- 不包含敌人、开火、命中、生命、弹匣、换弹或切换掩体。
- 不验证武器模型、瞄具、角色身体、战斗数值与 AI。
- 不决定正式 Unity 摄像机实现、动画方案或生产美术标准。
- 不用本实验直接改写 draft 战斗设计。

## 技术实验选择

- 使用 Three.js WebGL 构建真 3D 几何体，验证遮挡、横移、侧倾和视差。
- Three.js 作为本地 npm 依赖，由原有 Node 静态服务器映射给局域网设备，不依赖外部 CDN。
- 300ms 探出、240ms 缩回、约 7° 侧倾是本轮实验参数，不是正式技术契约。

## 成功判据

- 默认状态只看到近处遮挡面，不能看到通道纵深。
- 按住后摄像机连续探出，完全探出时可清晰看到通道纵深并感知侧倾。
- 松开后立即开始返回，并在 240ms 实验时长内恢复完全遮挡。
- 中途松开或返回途中再次按住不会跳变、卡死或反向错乱。
- 目标竖屏无滚动、浏览器缩放或 iOS 长按选择干扰。
- 页面不包含上一版战斗操作与状态。

## 失败与停止判据

- 未按住时仍能窥见通道内部。
- Peek 只表现为 UI 变形或平面移动，缺乏可感知空间视差。
- 松开后仍停留在暴露视角，或快速重按导致摄像机瞬移。
- 目标手机无法稳定运行 WebGL 场景。
