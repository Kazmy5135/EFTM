# DDR-001 真假 Peek、旧位置情报与辅助瞄准

## 背景

早期核心战斗草案使用“上滑架枪、下滑回撤”，并假设玩家不移动准星、不参与压枪。H5 摄像机原型在连续体感验证中逐步形成了另一套基础循环：玩家可以用假动作安全获取有限位置情报，再决定是否真架枪；系统根据最后观察位置提供初始预瞄，玩家仍可有限调瞄和压枪。

设计者于 2026-09-02 确认：取消上滑架枪和下滑回撤，把当前 H5 方向作为战斗模块 V1 的基础方向。该 V1 只覆盖最基础战斗模块，不代表完整战斗玩法或完整游戏范围。

## 约束

- 游戏运行在手机竖屏，核心循环必须单手可完成。
- 不复刻传统移动端 FPS 的完整双摇杆和持续高精度瞄准负担。
- 战斗结果不能完全自动化或退化为装备数值比较。
- 敌人隐藏后必须保留信息差，玩家不能获得实时透视。
- 假动作和真架枪必须具有不同收益、风险与承诺程度。
- H5 结果是设计证据，不自动成为 Unity 技术方案。

## 候选方案

### A. 上下滑控制架枪和回撤

- 优点：战场区域直接承载输入，按钮数量少。
- 缺点：真假动作难以清晰区分；滑动、调瞄和压枪容易争夺同一区域；短操作可能形成无风险试探。

### B. 真假 Peek 双操作加辅助瞄准

- 左侧点击真架枪，自动探出并保持；再次点击返回。
- 右侧按住假动作，松开返回，不能开火。
- 假动作获取最后位置情报，真架枪一次性预瞄旧位置。
- 玩家可以有限调瞄和压枪。

### C. 完整移动端 FPS 瞄准

- 优点：枪械控制自由度和传统 FPS 熟悉度最高。
- 缺点：明显增加单手负担，削弱项目以战术选择替代高强度微操的差异化目标。

## 决策

战斗模块 V1 采用候选方案 B，并废止上滑架枪、下滑回撤作为现行基础输入。

具体方向如下：

- 真架枪为点击后自动探出并保持的攻击承诺。
- 假动作为按住探出、松开返回且不能开火的低承诺观察。
- 假动作看到至少 `10%` 敌人轮廓后记录最后观察位置。
- 完全返回掩体后，以黄色透视剪影显示最后观察位置；下一次 Peek 开始时隐藏。
- 敌人完全不可见后有 `25%` 概率在五个候选点位间换位，因此剪影可能过期。
- 有新情报时，下一次真架枪一次性预瞄到旧位置；没有新情报时保留玩家上一次手动准星。
- 真架枪期间允许有限调瞄；按住开火时允许拖动压枪。
- 开火键在真架枪开始时即可按住预备，但完全探出前不产生射击。

## 理由

- 双操作直接表达“观察试探”和“攻击承诺”，比同一区域上下滑更容易建立可读的战术差异。
- 最后位置剪影让预瞄有明确来源，同时通过概率换位保留信息过期和欺骗空间。
- 一次性辅助预瞄降低手机瞄准负担，有限手动修正和压枪又让玩家仍能影响射击结果。
- 开火预备减少真架枪与第一发之间的输入等待，使单手操作更连续。
- 当前 H5 已为遮挡、侧倾、真假 Peek、预瞄、剪影、调瞄和后坐力提供可重复证据。

## 后果与验证

### 正向后果

- 核心循环从抽象“自动瞄准”变为可观察的情报获取、旧位置判断和攻击承诺。
- 玩家可以通过再次假 Peek 对抗过期情报，而不是只能盲猜。
- Unity 首个战斗切片可以围绕明确状态机推进，不必同时实现完整战斗系统。

### 代价与风险

- 黄色剪影可能被误解为实时透视，需要持续强化“旧位置”语义。
- 有限调瞄和压枪可能逐步膨胀成传统 FPS 操作负担。
- 两个 Peek 操作加开火键会占用更多屏幕区域，需要继续验证单手触达。
- `10%`、`25%`、五点位、`300ms/240ms` 和后坐力强度是 V1 初始参数，不是不可变的最终平衡值；调整时必须进入后续设计变更。

### 下一步门禁

1. `DESIGN-PRODUCT-DEFINITION`、`DESIGN-CORE-COMBAT` 与本 DDR 已由设计者批准为 accepted。
2. 建立 Unity 技术设计，明确摄像机、输入、状态、敌人位置、情报标记和射击职责。
3. Unity 首个实现只覆盖战斗模块 V1 基础切片，并以 H5 可观察行为作为对照，不复制 Three.js 代码结构。
4. 弹匣、伤害、切换掩体、手雷和敌人 AI 分别进入后续设计与验证。
