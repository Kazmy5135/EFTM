# EFTM 产品定义

## 文档目标

定义 EFTM 是什么产品、希望交付什么核心体验，以及首个 Demo 应验证什么。本文件只描述产品与玩家可观察体验，不决定具体代码结构或网络方案。

## 一句话定义

EFTM 是一款竖屏、单手为主的手机多人实时搜打撤游戏：多名玩家进入同一危险区域探索、搜集和争夺物资，并在生存资源耗尽或死亡前撤离；枪战采用以剪刀石头布式克制为核心的半回合制自动瞄准与手动触发射击，搜索采用适配单手操作的格子背包“华容道”，在不要求玩家移动准星和压枪的前提下提供战术、空间与风险博弈。

## 产品类型

- 平台与持机方式：手机竖屏，所有核心流程必须可以单手完成，第二只手只能提供可选辅助。
- 核心品类：多人搜打撤 / 撤离式生存。
- 战斗表现：实时世界中的半回合制枪战；角色自动完成瞄准与命中方向，玩家负责架枪时机和手动连续开火。
- 核心对抗：PvPvE；玩家既面对环境与机器人，也可能伏击或掠夺其他 PMC。
- 局外成长：物资积累、藏身处建设、商人任务、购买权限和高级区域解锁。
- 体验参照：希望在手机上复现《逃离塔科夫》由探索、资源、信息差、死亡损失和成功撤离共同构成的压力与成就感，而不是复刻其第一人称射击操作。

## 两大核心交互模块

### 1. 半回合制枪战

- 主要操作必须可以单手完成，允许第二只手提供少量可选辅助，但不能成为正常游玩的前提。
- 核心博弈采用“剪刀石头布”式相互克制：玩家通过可读的战术选择判断对手，而不是依靠手速、瞄准或压枪取胜。
- “剪刀、石头、布”目前代表关系模型，不预设最终一定是三个固定按钮；具体战术动作、情报和反制窗口将在战斗系统设计中确定。
- 武器、距离、掩体、伤势、装备和先手等真实枪战因素应影响选择与结果，但不能把博弈压缩为战力数字自动比较。

### 2. 搜索与格子背包“华容道”

- 搜索的核心操作是用一只手流畅地管理二维格子背包。
- 物品具有不同占格尺寸，背包具有有限且有形状的空间；玩家通过拿取、旋转、腾挪、替换或丢弃，为更重要的战利品创造连续空间。
- 搜索不是安全的整理界面。世界时间持续流动，停留越久，食物消耗和被其他 PMC 发现的风险越高。
- 核心决策是综合物品价值、单位格收益、即时用途、任务用途与暴露时间，决定“带什么、丢什么、还要整理多久”。
- 交互应保留空间取舍的乐趣，但不照搬 PC 鼠标的精确拖放负担；具体单手手势需由手机原型验证。

## 核心体验承诺

1. **不靠准星微操也能感到枪战真实。** 玩家不需要移动准星或压枪，但通过简单手势决定架枪、按住连续开火、回掩体和切换位置；武器、距离、掩体、伤势、装备、先手和战术选择应产生可信后果。
2. **简单输入承载战术克制。** 战斗操作适合竖屏单手，但选择之间形成清晰的判断、欺骗与反制关系。
3. **整理背包也是局内玩法。** 玩家在危险仍然流动时，用单手完成空间重排，并为是否继续搜刮承担风险。
4. **进入地图即承担风险。** 携带的装备与搜到的物资会因死亡而失去，成功撤离才能把收益带回局外。
5. **探索始终伴随取舍。** 食物等生存资源限制停留时间；继续深入、蹲守敌人或立即撤离都应有明确风险与收益。
6. **其他 PMC 是不可预测威胁。** 玩家可以避战、伏击、击杀和掠夺其他 PMC，形成信息差与遭遇故事。
7. **每次撤离推动长期成长。** 带回的物资用于藏身处、任务和交易权限，并逐步打开更高价值、更危险的区域。

## 目标玩家行为

- 战前选择携带装备、补给和可承受的损失。
- 与多名 PMC 一同进入地图。
- 探索区域并发现物资，以单手完成格子背包整理和携带取舍。
- 管理食物等持续消耗资源，判断剩余探索时间。
- 根据情报、地形、装备和风险决定避战、交战、伏击、追击或撤退；进入战斗后通过相互克制的战术选择与手动连续开火影响枪战。
- 在死亡或资源耗尽前到达撤离点并完成撤离。
- 将成功带回的物资用于仓储、藏身处、商人任务和后续出击。

## 核心循环

```text
整备与选择风险
→ 进入多人地图
→ 探索、搜集、观察与遭遇
→ 半回合枪战 / 避战 / 伏击 / 撤退
→ 在资源耗尽或死亡前尝试撤离
→ 带回物资或承担损失
→ 建设藏身处、完成任务、解锁交易与高级区域
→ 以更高目标再次出击
```

## 世界内时间与交互原则

- 地图中的探索与玩家关系是实时发生的，不采用彼此隔离的传统关卡回合。
- “半回合制”首先用于解决枪战过程和决策节奏，不代表整个地图暂停。
- 自动战斗不等于没有决策；玩家价值应从信息获取、战前准备、位置、交战条件、战术指令和风险管理中产生。
- 真实感优先指可信的因果关系、武器与伤势差异、死亡后果和战场压力，不等同于完整模拟现实中的全部细节。

## 长期进程

| 系统 | 玩家目的 | 与出击循环的关系 |
|---|---|---|
| 仓储与战利品 | 保存成功撤离带回的资源 | 决定后续可携带装备与可承受风险 |
| 藏身处 | 消耗资源建设长期能力 | 为搜集提供持续目标与资源出口 |
| 商人任务 | 完成指定目标 | 引导玩家接触不同区域、物资与行为 |
| 购买权限 | 解锁更多可购买内容 | 降低部分补给不确定性并提供成长反馈 |
| 区域解锁 | 进入更高价值和更高风险区域 | 形成中长期推进方向 |

## 首个可玩 Demo（V1）

### 目标

验证“实时探索 + 资源压力 + 半回合制自动瞄准与手动开火 + 死亡损失 + 成功撤离”能否在手机上形成一次完整且有张力的搜打撤体验。

### 包含

- 单张小型地图。
- 一个玩家 PMC 与若干机器人 PMC / 敌人共同活动。
- 基础探索、物资搜集和携带容量限制。
- 竖屏单手可完成的最小格子背包整理交互。
- 食物或等价生存资源随时间消耗。
- 最小可用的遭遇与半回合制枪战。
- 最小可用的剪刀石头布式战术克制关系。
- 死亡丢失本局携带物，成功撤离带回物资。
- 最小局外仓储，以及能够展示“带回物资有价值”的一个成长出口。

### 不包含

- 首版不要求接入真人玩家。
- 首版不决定最终采用异步真人映射还是真人同步在线。
- 首版不追求完整藏身处、商人经济、任务链或多区域内容量。
- 首版不追求完整复刻《逃离塔科夫》的武器、伤势、改装和经济复杂度。

## 成功标准

- 玩家无需进行准星瞄准和压枪，通过按住单键连续开火即可理解枪战结果为何发生，并能指出自己此前的至少一个有效决策。
- 正常游玩时，战斗与搜索的必需操作均可由一只手完成。
- 玩家能流畅完成物品拿取、旋转、腾挪、替换和丢弃，并能理解物品为什么装不下。
- 至少三类战术选择形成可理解的相互克制，不存在一个在常规情境下恒定最优的选项。
- 一局中至少出现一次“继续搜还是撤离”的真实取舍。
- 获得高价值物资后，玩家对死亡损失产生明显顾虑。
- 遭遇其他 PMC 时，避战、伏击、交战或撤退至少有两种可行选择，而不是固定进入战斗。
- 成功撤离与死亡在局外产生清晰且不同的结果。
- 一次完整循环适合手机使用情境；具体目标局长在后续节奏设计中确定。

## 关键风险

| 风险 | 需要验证的问题 |
|---|---|
| 自动战斗变成纯数值比较 | 玩家在战斗前和战斗中是否拥有足够可理解、可影响结果的决策？ |
| 剪刀石头布变成盲猜 | 玩家能否通过情报、行为和风险推断对方选择，而不是没有依据地碰运气？ |
| 半回合战斗与实时多人冲突 | 交战期间其他实体如何继续行动，才能兼顾公平、可读性与伏击可能？ |
| 背包整理变成触屏苦工 | 能否在保留空间取舍时，让一根拇指可靠完成所有高频动作？ |
| 真实感与手机节奏冲突 | 哪些真实规则构成体验，哪些只会增加操作和等待负担？ |
| 机器人无法代表真人压力 | V1 应记录哪些行为数据，才能判断未来需要异步真人还是真人同步？ |
| 局外成长压过单局体验 | 即使内容量很小，单次探索与撤离是否本身成立？ |

## 待决策

1. 玩家在探索地图时采用什么视角和移动交互方式。
2. 剪刀石头布关系具体由哪些战术动作构成，玩家在每个半回合获得什么情报。
3. 手动按住连续开火的节奏、武器差异和信息负担，是否仍满足“不要复刻移动端 FPS 微操”的产品承诺。
4. 半回合制枪战的时间模型，以及交战时其他 PMC 如何介入。
5. 格子背包的拿取、落位、旋转、交换、快速收纳和中断手势。
6. 首个 Demo 的目标单局时长、地图规模和同时存在的 PMC 数量。
7. 食物耗尽的精确后果：直接失败、持续伤害、能力下降或迫使撤离。
8. V1 最小成长出口采用仓储、藏身处设施、商人任务还是其中的组合。
9. 正式版本采用异步真人映射、真人同步在线，还是分阶段混合方案。
10. 目标性能档位和最低支持设备。
