# AGENTS.md - EFTM H5 原型开发

## 定位与触发条件

`H5Prototype/` 用于设计者明确提出的体感、交互或可用性验证。它是按需启用的实验工作区，不是所有设计的固定环节，也不是 Unity 开发的通用门禁。

只有同时满足以下条件才开始 H5 原型任务：

1. 设计者明确要求使用 H5 验证；
2. 对应工作项或对话明确给出验证假设和原型范围；
3. 已知成功/失败判据以及原型的非目标。

不满足时，报告缺失的交接信息，不自行把普通设计任务扩展为 H5 开发。

## 负责范围

- 手机竖屏交互、操作节奏、信息反馈和可用性原型。
- 为单个验证假设构建最小可运行实验。
- 原型运行说明、自动化检查和验证证据。
- 明确记录观察结果、技术限制和未覆盖场景。

## 不负责

- 决定正式玩法规则或批准设计。
- 把原型代码、临时数值或视觉占位当作生产契约。
- 修改 `UnityProject/` 中的正式实现。
- 因为原型存在而要求其他设计补做 H5。

## 阅读顺序

1. 根目录 `AGENTS.md`
2. `Docs/00_Project/Agents/H5PrototypeAgent.md`
3. 设计者交接中列出的工作项和设计文档
4. 本目录 `README.md`
5. 与当前原型直接相关的代码与测试

不要默认扫描全部设计文档或 Unity 工程。

## 实验与证据规则

- 每个原型必须绑定一个工作项或明确的验证请求。
- 在代码和说明中标记实验性质、验证目标和清理方式。
- 临时规则、占位资源和模拟数据不得被描述为正式设计。
- 结果必须区分“观察到的行为”“参与者反馈”“agent 推论”和“设计者结论”。
- H5 发现设计问题时回传策划设计 agent，由设计流程决定是否修改正式基线。
- 只有工作项明确要求时才更新 `Docs/30_Iterations/**/Validation.md`；不得直接修改 accepted 设计语义。

## 技术规则

- 当前目录不预设前端框架；首次实际原型任务根据验证目标选择最小技术方案，并在 `README.md` 记录启动和测试方式。
- 优先保持原型可本地运行、可重复验证、易于删除或替换。
- 依赖版本、构建产物和测试报告按根 `.gitignore` 与项目说明管理。
- 完成前至少执行构建或静态检查、相关测试以及目标视口下的人工验证。
